# R82 — содержательная доработка и сохраняемая редакция

Главное правило: общий механизм для разных тем; не принимать полноту полей за качество. Критерии и их определения находятся в artifact_review, привязаны к неизменному тексту и единицам документа. Положительный основной аудит дополняется чтением другой моделью; авторы исключены из обоих мнений. Неопределённый результат блокирует завершение.

Экспорт использует общий HTML renderer с Markdown и карточками распознанных публикаций. Сохранённый исходный Markdown/TXT не меняется. Неизвестные услуги и бизнес-факты не выдумываются ради конкретности; повтор CTA/KPI сам по себе не означает повтор смысла.

## A75.30: новое случайное задание на каждую модель и сокращение повторных прогонов (R19)

Исправлено несоответствие пользовательскому требованию: вместо клонирования одного брифа на все модели каждый автор получает отдельное случайное синтетическое задание; за один прогон категории не повторяются, если доступно достаточно категорий. Модели-авторы по-прежнему выбираются случайно и без повторов; seed фиксирует модель/задание назначения для воспроизведения. Сравнение агрегирует результаты на разнообразных брифах и не выдаёт их за парное A/B-сравнение одного задания.

В acceptance целиком задание больше не перезапускается повторно после неудачного завершения: один кейс — один авторский прогон; встроенное восстановление отдельных документов и независимая проверка остаются. Интерактивный production flow сохраняет прежний бюджет полного повтора. Это сокращает дорогие дублирующие вызовы и делает выборку модели прозрачнее.

Для стратегии добавлен структурированный JSON-контракт с обязательными разделами, KPI и способами измерения. Хост строит документ из проверенной схемы, а не просит модель самостоятельно помнить разрозненный Markdown-чеклист. Независимые проверки фактов и содержания остаются обязательными; этот формат не гарантирует высокое качество вывода.

R19 остаётся NOT RELEASE. Нужно новое Windows/Ollama acceptance с пятью разными случайными брифами, чтобы проверить, устранило ли это изменение реальный блокер качества. Исходников Stage 76 нет.

## A75.32: разделение контракта контент-плана и готовых публикаций (R22)
