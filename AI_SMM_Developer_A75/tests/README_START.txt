DEVELOPMENT SNAPSHOT — NOT RELEASE

ЗАПУСК ПРОВЕРКИ
Распакуйте весь комплект в новую папку. В AI_SMM_Work_Architecture_A75 запустите RUN_ARCHITECTURE_CHECK.cmd. Профиль fast проверяет оба вида работы: одиночный пост и стратегию с календарём на разных случайных заданиях. Если допустим только один автор, оба задания выполняет он; отчёт честно показывает одного автора и неполное сравнение моделей. Итог: VALIDATION_RESULTS.zip.
CHECK_REVIEWERS.cmd по-прежнему выполняет только короткий контроль моделей; он не проверяет качество генерации. Приложение: RUN_AI_SMM_MANAGER.cmd.

ЧТО ПОКАЗАЛ ВАШ R69
GPT-OSS и Gemma4 прошли 6/6 контрольных решений; Qwen3 — 3/6. У Llama, DeepSeek, Mistral и Gemma3 пакет не прошёл контракт, поэтому смысловые ответы не оценены. Время всех обращений около 95 секунд. Контент не генерировался. Требование пяти квалифицированных семейств блокировало работу даже при двух подходящих редакторах.

ОБЩАЯ ПОЛИТИКА R70
Четыре критерия сохранены: требования, полнота, источники, формат/тон. Их число отделено от числа моделей. Нужны минимум две квалифицированные семьи редакторов помимо автора. Source/арбитр отделён от каждого редактора, чьи замечания он оценивает. Редактор может проверять несколько критериев. При достаточном пуле используются четыре разных голоса; модели, не прошедшие 6/6, редакторами не становятся.
Автор и редакторы выбираются из разных ролевых списков. Неверный контракт арбитражного решения не доказывает неспособность быть автором: завершённый структурированный ответ допускает модель только как кандидата в авторы; реальный генератор отдельно проверяет свой контракт, а текст принимают квалифицированные редакторы. Автор без двух независимых квалифицированных рецензентов откладывается с явной причиной. По вашему R69 доступная комбинация — Qwen3-автор и GPT-OSS/Gemma4-редакторы; это не жёстко заданные имена в алгоритме. При недостатке ёмкости для нового автора правки остаётся исходный автор с независимыми проверками; причина видна в generation_roles/quality_review. Одобрение всё равно требует полного прохождения критериев.
Один доступный автор не превращается в двух в отчёте: ему создаются два разных случайных задания для двух маршрутов. Coverage модели отмечается отдельно от покрытия маршрутов.
Первичная ошибка контрактного ответа и сам ответ контрольного задания теперь сохраняются. Ограничение одного запроса не маскирует эту ошибку. При невалидном контракте semantic_controls_evaluated=0; это не доказанные 0 правильных ответов из 6. В дочернюю среду передаются компактные положительные свидетельства, без больших сырых ответов.
