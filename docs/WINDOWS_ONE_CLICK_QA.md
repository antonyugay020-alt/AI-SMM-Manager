# Windows QA одним запуском: RTX 3080 Ti → RTX 2080 Super

Это проверка исходников существующего PR #4. Пользовательский релиз, установщик
и промежуточная сборка не создаются. Скрипт не скачивает модели, не устанавливает
пакеты, не запускает платные API/Actions и не отправляет отчёты в облако.

## Единственное место для отчёта

**Больше не ищите архивы внутри папок с датами и номерами запусков.**
После каждого завершённого запуска (PASS или BLOCKED) программа автоматически
публикует готовый ZIP по одному постоянному пути:

`%USERPROFILE%\Desktop\AI_SMM_REPORTS\DIAGNOSTICS.zip`

В этой же папке находится `STATUS.json` с итоговым статусом.
Все внутренние сессии и доказательства остаются для технической трассировки;
пользователю не нужно открывать их или искать `run_01\report`.
Новый успешный архив атомарно заменяет предыдущий готовый архив. Если QA
остановится до создания полного отчёта, тот же путь будет содержать ZIP с
ошибкой, статусом, журналом и доступными доказательствами последнего прогона.
Провал второго/последующего прогона никогда не подменяется архивом первого.

## Что запустить

На RTX 3080 Ti обновите исходники **integration/ai-smm-pr2-20261106** и откройте
в корне **RUN_WINDOWS_QA.cmd**, выберите **1**. После исправления всех найденных
ошибок повторите на финальном составе. Успешная первичная проверка создаст
`PRELIMINARY_ATTESTATION.json` в папке сессии.

На RTX 2080 Super 8 GB используйте те же исходники и те же веса/входные файлы,
при необходимости скопируйте папку исходников по LAN без `.venv` (байты, включая
окончания строк, должны совпадать), откройте **RUN_WINDOWS_QA.cmd**, выберите **2** и укажите этот файл с RTX 3080 Ti.
Его можно скопировать по локальной сети; удалённый доступ Work не нужен.
Скрипт сам выполнит **10 полных последовательных прогонов**. Любая ошибка,
неопределённый вердикт, изменение исходников/весов/зависимостей/моделей или
входных материалов сбрасывает счётчик до нуля и останавливает сессию.
Следующий запуск начинает новый цикл с 0; прошлые отчёты не удаляются.

Прогон на RTX 3080 Ti никогда не увеличивает целевой счётчик. Результат 10/10
относится к полной Windows Qt E2E-проверке исходников. Приёмка конечного
упакованного дистрибутива, независимый review и остальные release-гейты
сохраняются; `release_eligible` остаётся false. Скрипт не выполняет merge/release.

## Однократная подготовка на каждом ПК

Нужны Python **3.12 x64**, уже установленные FFmpeg/ffprobe в PATH, драйвер
NVIDIA с `nvidia-smi`, работающая локальная Ollama и отдельный CUDA Python
в профилях генеративных моделей. Если чего-либо нет, сохраняется BLOCKED с
диагностикой; ничего не загружается автоматически.

Для основного Python QA один раз установите свободные зависимости:

```bat
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-qa.txt
```

Launcher предпочитает `.venv\Scripts\python.exe`, затем `py -3.12`.
Для другого уже настроенного окружения задайте `AI_SMM_QA_PYTHON` полным путём.
Зависимости Diffusers остаются в отдельном Python каждого модельного профиля,
чтобы не конфликтовать с Gradio/Hugging Face Hub в основном приложении.

**Большие модели устанавливаются только после вашего отдельного подтверждения.**
QA никогда не вызывает download/`ollama pull`. При отсутствии весов сначала
сохраните диагностику и согласуйте подготовку моделей. Нужны все четыре
профиля из [описания генеративной архитектуры](LOCAL_GENERATIVE_MEDIA.md):
InstructPix2Pix, SD 1.5 IP-Adapter, inpainting, AnimateDiff V2V с IP-Adapter.
Тестовые мини-модели и CPU-профили в Windows-приёмку не допускаются.

Для автоматической проверки смысла изображения/видео нужна **уже установленная
локальная vision-модель Ollama**. Она проверяется на двух пиксельных контролях;
неверный/неполный/UNCERTAIN ответ не засчитывается. Для полного текстового
контура также нужны локальные автор и независимые редакторы разных семейств,
проходящие существующую квалификацию приложения. Облачные теги и внешние API
запрещены даже при наличии ключей в окружении. Список `local_models` можно
явно ограничить в settings.json; embedding-модели в QA-авторы не попадают.

На первом запуске мастер:

1. Предложит выбрать один или несколько JSON с существующими профилями весов.
2. Предложит план — можно взять `docs/WINDOWS_GENERATIVE_PLAN.example.json`.
3. Спросит точный установленный тег локальной vision-модели.
4. Поможет сопоставить имена профилей плана и выбрать отсутствующие реальные
   фото, эталон, две маски и ролик со звуком. Повторяющиеся пути выбираются один раз.

Выбранные settings/профили/план сохраняются рядом с отчётами для следующих
запусков. Маски должны иметь размер исходного фото: белое меняется, чёрное
сохраняется. Материалы на двух ПК могут лежать по разным путям, но их байты,
параметры задач, веса и версии сред должны совпадать. После изменения кода
старый первичный отчёт отвергается: сначала снова проверьте RTX 3080 Ti.

## Что входит в каждый полный прогон

- Новая чистая копия исходников, свежий случайный seed текстовых задач,
  отдельные SQLite/проекты; рабочая база пользователя не открывается.
- Вся регрессия разработчика и CI-контракты. Их offscreen/fixture-проверки
  явно отделены от настоящих видимых Windows Qt и реальных модельных задач.
- Существующий полный live Qt/text/model workflow, независимая проверка текста,
  навигация, изоляция проектов и экспорт PDF.
- Реальная CUDA/FP16-генерация всеми четырьмя движками: стиль, фон, объект/детали
  по маске, эталон, V2V и V2V с эталоном. Ограничения целевых 8 GB действуют
  и на RTX 3080 Ti; превышение целевого резерва памяти не игнорируется.
- Истинные пики allocated/reserved VRAM дочернего Torch-процесса; одновременно
  ежесекундные замеры `nvidia-smi` по всей карте. Последние включают Ollama и
  другие приложения и не выдаются за память только Diffusers.
- Декодирование результатов, геометрия/длительность, непустые/изменённые кадры,
  точная сохранность чёрной области маски, sampled flicker и корреляция
  исходного/выходного аудио. Семантика, соответствие эталону и связность кадров
  дополнительно оцениваются квалифицированной локальной vision-моделью.
- Остановка после запуска настоящего дочернего процесса, авария его владельца,
  завершение потомка по EOF, восстановление прежнего job ID, повтор генерации,
  независимое открытие SQLite, `integrity_check`, SHA-256 результатов и
  принятие готового receipt без повторной генерации.
- Win32 Job Object владеет только деревом QA-процессов, назначается до начала
  исполнения и завершает своих потомков при аварии/тайм-ауте. Никаких глобальных
  `taskkill` по именам приложений или остановки чужих процессов.

Автоматический vision-вердикт — измеримая модельная оценка, **не гарантия
безошибочной художественной/фактической оценки**. Полные изображения, ролики,
маски, observations и метрики сохраняются для проверки человеком. Звук
сравнивается на первых двух секундах с компенсацией до ±64 мс; это не полный
перцептивный аудиоанализ. Отмена/авария проверяются на стадии запуска процесса,
а не во всех возможных фазах CUDA kernel. Эти границы указаны и в отчётах.

## Одна папка для всех результатов

**`%USERPROFILE%\Desktop\AI_SMM_REPORTS`**

- `STATUS.json` — актуальный этап, статус и целевой счётчик.
- `LATEST.json` — путь последней сессии.
- `BOOTSTRAP_CONSOLE.txt`, `BOOTSTRAP_STATUS.txt` — в том числе ошибка до старта Python.
- `settings.json`, `selected_profiles.json`, `selected_plan.json` — ваш локальный выбор.
- Папка сессии: `HOST.json`, `PREREQUISITES.json`, `preflight.json`, source manifest,
  `STATUS.json`, при успехе RTX 3080 Ti — `PRELIMINARY_ATTESTATION.json`.
- `run_01` … `run_10`: чистые копии, консоль, VRAM JSONL, `report/acceptance.json`,
  полный CI/JUnit, сохранённые исходные QA-проекты/SQLite/экспорты,
  `generative_media` с PNG/MP4, скриншотами, receipts, метриками и quality.json.
- `REPORT_MANIFEST.json` — SHA-256 всех файлов сессии.
- `report/DIAGNOSTICS.zip` — дополнительный архив диагностики, **не сборка программы**.

Если запуск BLOCKED, не удаляйте сессию. Для разбора предоставьте папку этой
сессии; автоматической отправки, GitHub Actions и расходов нет. Закройте другие
GPU-нагрузки и не меняйте окружение/исходники во время десяти прогонов. QA может
занять много часов: он не подменяет реальные локальные модели быстрыми ответами.

В Work проверены только доступные Linux/CPU механизмы и контракты. Фактические
счётчики на RTX 3080 Ti и RTX 2080 Super остаются **0**, пока запуск не выполнен
на соответствующем компьютере.

## First real Windows QA follow-up (2026-11-09)

Reports use the single desktop folder `%USERPROFILE%\Desktop\AI_SMM_REPORTS`.
When a nonmask image was selected as an inpaint auxiliary, the QA supervisor
creates deterministic, binary, checksum-recorded, QA-only PNG masks in its
`QA_FIXTURES` subfolder and preserves the user's original source bytes.
Provenance is written into each QA session as `qa_fixture_mask_provenance.json`.
A true matching binary PNG mask is accepted unchanged. This is test input
preparation, not proof of artistic quality or a production mask generator.

The independent reviewer six-control oracle and family requirements remain
unchanged; the local candidate's cold-start network deadline is 180 seconds,
with no cloud/API fallback. CUDA generation emits stage markers, gives a
nonresponding child 180 seconds to start, bounds GPU device-lock waiting,
and retains failure job evidence. No success is inferred from interrupted
or hung generation, and Windows 0/10 remains until verified on both hosts.
