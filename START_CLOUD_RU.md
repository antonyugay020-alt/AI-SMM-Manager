## Один обязательный организационный шаг

В подключённом GitHub сейчас нет доступного репозитория. Создайте **приватный** репозиторий (например, `ai-smm-manager`), не добавляя README/лицензию/шаблон при создании, и дайте подключённому GitHub-приложению доступ. После этого репозиторий можно заполнить через облачный Git / ChatGPT Work из вложенного Git bundle — без каких-либо изменений исходников на домашнем ПК.

Пример команды для **облачной Git-среды**, а не твоего Windows-ПК:

```bash
git clone -b main ai_smm_cloud_repo.bundle ai-smm-manager
cd ai-smm-manager
git remote add origin https://github.com/OWNER/ai-smm-manager.git
git push -u origin main
```

Заменить `OWNER` владельцем нового репозитория. Вход в GitHub должен быть настроен в облачной Git-среде; токен нельзя вставлять в сообщения или сохранять в репозитории.

После этого настроить секреты GitHub Actions (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `ALT_REVIEW_API_KEY`) и имена моделей в Variables; можно подключать каждый сторонний сервис независимо. Отсутствующая модель/ключ блокирует соответствующий аудит, а не подменяется имитацией.

**Полная Windows-приёмка:** для реально интерактивного PySide6 GUI нужна отдельная облачная Windows VM с GPU, Ollama и self-hosted GitHub Actions runner с меткой `smm-cloud-qa`. Обычный GitHub-hosted Windows runner выполняет кодовую регрессию, но не считается доказательством полного интерактивного E2E.

Непроверенное: реальный облачный запуск Codex, доступность Claude/Qwen/DeepSeek, Windows CI, GUI E2E, 10 последовательных чистых циклов. Счётчик выпуска — **0/10**.
